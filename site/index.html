drive-replay

Recorded drives replayed through an ADAS stack on x86. One run command that resolves everything itself, bug replay that reproduces an issue from its recording and proves the fix, and a replay CI that gives every build drop a PASS or FAIL verdict. Stack under test: a C++17 radar forward collision warning, built with Bazel. Recordings: 10 real nuScenes drives (front radar) plus 3 must-warn cases with an injected target.

Code on GitHub docs/RESULTS.md

CI verdict per build drop

Every drop replayed through the current suite: runs, deterministic (two replays, same digests), requirements (ground-truth oracle) and regression (golden baselines). Hover a FAIL for the reason.

Bug replays

Pre-roll study

A bug window starts 0.1 s before a known warning. Does the window replay give exactly the events of the whole-drive replay? Without pre-roll the tracker starts cold and the warning moves. Note the 1.0 s row of the stopped-car case: more pre-roll is not always closer, which is why replay bug checks fidelity every time.

Throughput and determinism

Vehicle dynamics (v0.3.0)

Kinematic and linear dynamic single-track models (C++17, RK4) with parameters identified from the nuScenes CAN bus data (steering, wheel speeds, IMU) of the training drives, evaluated on held-out test drives. 95 % bootstrap intervals over scenes. Full write-up: docs/VEHICLE_DYNAMICS.md.
